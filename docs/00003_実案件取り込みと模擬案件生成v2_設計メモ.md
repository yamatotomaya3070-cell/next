設計判断:

1. **テナント分離は「列の追加」まで**。既存テーブルのRLSを今すぐ施設スコープにすると単一施設運用が壊れるため、`current_facility_id()` ヘルパーだけ用意し、RLSの施設強制はSaaS化時の専用マイグレーションで行う（移行手順: backfill → not null化 → ポリシー差し替え）。
2. **RAGへは匿名化済みテキストのみ格納**。`real_cases.raw_content`（原文）と `case_documents.content`（匿名化済み）をテーブルで物理分離し、生成プロンプトが原文に触れない構造にした。
3. **埋め込みは768次元**（Gemini `text-embedding-004`）。モデル変更時は列定義とインデックスの張り直しが必要。
4. **`knowledge_base`（00001）は将来廃止候補**。`real_cases`+`case_documents` が上位互換のため、移行後に drop するマイグレーションを別途作成する。

適用前の確認事項:
- Supabase で `vector` 拡張の有効化が必要
- HNSWインデックスは pgvector 0.5+（現行Supabaseは対応済み）

## 2. 模擬案件生成v2（実案件→類似案件）のパイプライン

```
実案件テキスト(コピペ/メール)
  → [ステップ1] 匿名化・構造化  (temperature 0.2)
       出力: maskedCaseText / genre / skillTags / difficulty / maskingReport
  → [ステップ2] 類似案件一式の生成 (temperature 0.7)
       入力: 匿名化済みテキスト + RAG参考例(referenceSnippets) + 配慮メモ
       出力: 依頼書 / 手順書 / 台本 / セルフチェック / 修正指示 / 完成見本説明
  → 職員承認（maskingReport.riskNotes を承認画面に必ず表示）
  → tasks + task_materials へ保存、maskedCaseText は case_documents へ
```

- 2段階に分けた理由: 匿名化は「創作しない・低温度・厳格ルール」、案件生成は「創作する・高温度」で要求が相反するため。1プロンプトに混ぜると匿名化漏れが起きやすい。
- `revisionNote`（修正指示文）と `sampleDescription`（完成見本説明）を追加した。既存の `material_kind` の `revision_note` / `sample` にそのまま保存できる。
- モック実装（`GEMINI_API_KEY` 未設定時）は正規表現の簡易マスキングのみ。**店名・人名などは除去できない**ため riskNotes で職員確認を必須にしている。

## 5. 素材動画の自動生成（フェーズ1.5プロトタイプ・2026-07-19追加）

パイプライン: **台本生成(AI) → 音声合成 → 動画合成(ffmpeg) → 正解データ出力**

```
generateSourceScript(theme, targetKeepSeconds, difficulty)   … src/lib/ai/
  → 台本セグメント配列（keep=残す / cut=フィラー・言い間違い・沈黙・リテイク）
scripts/generate-source-video.ts
  → セグメントごとにTTSでWAV化 → スライド映像+音声のMP4断片 → 連結
  → answer.json（各セグメントの start/end 秒、cut/keep、カット理由、完成尺）
```

- 正解データが台本生成の副産物として得られるのがこの方式の核。提出動画の尺・カット箇所を answer.json と照合すれば**内容ベースの機械検品**ができる（v2 フェーズ1.5後半）。
- ローカルプロトタイプは Windows SAPI（Microsoft Haruka）+ ffmpeg。**本番では TTS を VOICEVOX またはクラウドTTS に、実行をサーバー側（ジョブキュー）に差し替える**。インターフェイス（script.json / answer.json）は据え置きで差し替え可能。
- 現状の制約:
  - スライドに発話テキストをそのまま表示するため、目視でもカット箇所を推測できてしまう（難易度1相当）。難易度を上げるにはテキスト非表示・話速変化・実写素材ライブラリとの合成が必要
  - 沈黙セグメントは文字なし背景のみ（視覚的にネタバレしない）
  - SAPIの音質は本番想定より低い。品質要件は v2 §9-2（合成音声のすり合わせ事項）
- 保存先マッピング: source.mp4 → `materials` バケット + `task_materials` (kind=`source_video`, media_url)、answer.json → `material_answers.answer_data`（**職員専用RLSの別テーブル**。task_materials の列にすると承認済み教材の閲覧権限で利用者に正解が漏れるため分離した。migration 00004）
