# Astra 6向け 動画編集学習システム改善指示書

作成日: 2026-09-11  
対象リポジトリ: `kizuna-video-training`

## 0. この文書の前提

この文書を使用する人は、修正内容を作成して依頼した側ではなく、依頼者から修正内容を受領した開発者である。

記載している指摘は、廣田さんによる実作業の確認結果を依頼者側が文章にまとめ、開発者へ共有したものである。現状のギャップはコード上の確認結果を含むが、改善方法、開発範囲、完成デザイン、担当、納期は依頼者との方向性打ち合わせで確定する。

会議前の段階では、本書の改善案を確定仕様として扱わない。会議後に合意した項目だけをAstra 6の実装プロンプトへ反映する。

## 1. この改善の目的

現在のシステムは、案件、素材、編集指示、提出、レビューの仕組みを持っている。しかし、利用者がDaVinci Resolveの基本操作を身につける導線と、支給素材だけで完成見本を再現できる条件が不足している。

今回の目的は、利用者が次の順番で学び、最終的に自力で動画を編集・提出・修正できる状態を作ることである。

1. 使用するDaVinci Resolveのバージョンに合った基本操作を学ぶ
2. 簡単な練習で各操作を確認する
3. 素材名、セリフ、順番を中心とした指示書を見て編集する
4. 必要な箇所だけフレーム単位の間を入れる
5. 支給素材だけで、指定された完成形を再現する
6. 動画を提出し、現在の確認状況と次の行動を理解する
7. フィードバックを受けて修正し、完了する

## 2. 現在のシステムで確認できたこと

### 2-1. 現在の基本フロー

現在は、おおむね次の流れになっている。

1. 職員がテーマを入力する
2. AIがシーン設計を生成する
3. 完成見本動画を生成する
4. 利用者向けに図解、立ち絵、音声、BGMを生成する
5. タイミング表、手順書、編集指示書を生成する
6. 課題として登録・割り当てする
7. 利用者が素材をダウンロードして編集する
8. 利用者が動画を提出する
9. AI採点結果を職員が確認する
10. 職員が承認すると利用者にフィードバックが表示される

主な実装箇所:

- `scripts/scene/worker.ts`
- `poc/scene/build_materials.mjs`
- `poc/scene/build_manual.mjs`
- `poc/scene/build_app_task.mjs`
- `scripts/scene/registerSceneTask.ts`
- `src/app/(trainee)/tasks/[id]/page.tsx`
- `src/lib/actions/assignments.ts`
- `src/app/staff/reviews/page.tsx`
- `src/lib/actions/staff.ts`

### 2-2. 現在利用できる仕組み

- 練習課題と実案件を管理できる
- 依頼書、作業手順、字幕台本、修正指示、素材ZIPを表示できる
- 手順を1工程ずつ表示できる
- 読み上げ、ふりがな、大きな文字、休憩通知に対応している
- 動画の提出と再提出ができる
- AI採点と職員承認の仕組みがある
- 職員が手順書を編集し、改善ルールを蓄積できる
- 完成見本と支給素材を生成できる

これらは残し、動画編集を習得する導線と、指示・素材・見本の整合性を追加する。

## 4. 目標とする利用者の学習フロー

### ステップ1: 環境確認

- 使用中のDaVinci Resolveバージョンを表示・選択する
- 教材が対象としているバージョンを表示する
- 画面が教材と違う場合の「表示をONにする手順」を案内する
- 職員が利用者ごとの利用バージョンを確認できる

### ステップ2: 基本操作コース

最低限、次の教材を順番に学ぶ。

1. プロジェクト作成と24fps設定
2. 素材の読み込み
3. 音声を順番に並べる
4. 必要な箇所にフレーム単位で間を入れる
5. 画像と動画素材を配置する
6. 字幕を入れる
7. 強調テロップを入れる
8. BGMと音声音量を調整する
9. MP4/H.264で書き出す
10. システムへ提出する

各教材は、説明動画、短い手順、練習課題、完了確認を持つ。職員は受講済みを手動でも承認できるようにする。

### ステップ3: 操作別の小さな練習

- 音声2個を指定順に並べる
- 1箇所だけ12フレーム空ける
- 画像を字幕安全領域内に配置する
- 見本と同じ字幕スタイルを作る
- BGMを声の邪魔にならない範囲へ調整する
- 指定形式で書き出す

最初から長い完成動画を作らせず、操作単位で成功体験を作る。

### ステップ4: 統合練習案件

基礎教材を終えた利用者へ、短い案件を割り当てる。指示書は秒数表ではなく、次の列を基本とする。

| 順番 | シーン | セクション | 映像タイプ | 話者 | セリフ | 使用する音声 | 使用する映像素材 | この後の間 | 補足 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | S1 | 導入 | 会話 | ミナ先生 | こんにちは | S01_01_ミナ先生.wav | S01_intro.mp4 | なし | 字幕スタイルA |
| 2 | S1 | 導入 | 会話 | ハル | よろしくお願いします | S01_02_ハル.wav | 継続 | 12フレーム | 発言後だけ空ける |

開始秒・終了秒は利用者向けには表示しない。完成見本の生成、プレビュー、機械検品に必要な秒数は内部データとして保持する。

### ステップ5: 提出とレビュー

提出後は次を表示する。

- 提出完了日時
- 現在の状態: AI確認中、職員確認待ち、修正依頼あり、完了
- 現在の担当: システムまたは職員
- 利用者が今すること: 待つ、修正する、完了を確認する
- 最終更新日時
- 再提出が必要かどうか

## 5. 編集指示の共通仕様

### 5-1. 利用者向け編集指示

利用者向けデータは、少なくとも次の形にする。

```ts
interface EditorInstructionRow {
  order: number;
  sceneId: string;
  section: string;
  visualType: string;
  speaker: string | null;
  dialogue: string | null;
  audioFile: string | null;
  visualAssetFile: string | null;
  visualAssetMode: "static_image" | "animated_clip" | "character_assets";
  gapAfterFrames: number | null;
  subtitleStyleId: string | null;
  emphasisText: string[];
  emphasisStyleId: string | null;
  notes: string[];
}
```

禁止事項:

- 利用者向けの表に絶対開始秒・終了秒を必須項目として出さない
- `8.6秒から開始`のような小数秒を作業条件にしない
- 「見本のように」「画面いっぱい」「いい感じに」だけで終わる曖昧な指示を出さない
- 支給していない加工やアニメーションを要求しない

### 5-2. 内部レンダリング用データ

完成見本と検品用には、現在の内部タイミングを残してよい。ただし、24fpsのフレーム境界へ丸める。

```ts
interface InternalTimelineRow {
  sceneId: string;
  startFrame: number;
  endFrame: number;
  fps: 24;
}
```

秒へ変換する場合は `frame / fps` を使い、秒を先に決めてから端数フレームを作らない。

### 5-3. 字幕スタイル

見本生成と指示書で同じデータを使用する。

```ts
interface SubtitleStyle {
  id: string;
  bodyColor: string;
  fontFamily: string;
  fontSize: number;
  fontWeight: number;
  maxLines: number;
  position: "bottom_safe_area";
  backgroundColor: string;
  speakerLabel: {
    visible: boolean;
    narratorColor: string;
    haruColor: string;
    minaColor: string;
  };
}
```

現在の見本に合わせる場合は、本文を共通色にし、話者名と左帯だけを話者色にする。

### 5-4. 図解の安全領域

- 1280×720の場合、字幕が使用する下部領域を図解の重要情報から除外する
- 素材ごとに`fit`または`fill`を指定する
- 比率が合わない場合の背景色・背景画像を指定する
- 利用者へパーセント値だけを渡すのではなく、プレビューで安全領域内に入っていることを示す

### 5-5. 強調テロップ

最低限、次を指示する。

- 表示文字
- フォント
- 太さ
- サイズ
- 文字色
- 背景・縁取り
- 位置
- 表示方法
- 対象シーン

### 5-6. BGM

- 一律の値だけで合否を決めない
- 初期値と許容調整範囲を示す
- 「ナレーションが明瞭に聞こえること」を確認項目にする
- 可能ならラウドネスまたは声とBGMの相対値を内部検品に利用する
- 見本生成と利用者向け素材で同じBGMファイルを使う

### 5-7. 動く素材

動きが完成条件に含まれるシーンでは、次のいずれかを支給する。

1. アニメーション済みMP4またはWebM
2. 透過動画
3. 個別パーツと、再現可能な具体的アニメーション指示

初期実装は1を優先する。数字、グラフ、順番表示を利用者側で一から作らせない。

公開前検査では、見本が動いているのに`static_image`しか支給されていないシーンをエラーにする。

## 6. システム改修の優先順

### Phase 1: 利用不能につながる矛盾を止める

1. 利用者向け絶対秒数を廃止する
2. 字幕、図解、強調テロップ、BGMの指示を見本と統一する
3. 動くシーンにアニメーション済み素材を支給する
4. 案件公開前の整合性検査を追加する
5. 提出時に必ず職員レビュー待ちレコードを作る
6. 提出後の状態と次の行動を表示する

### Phase 2: 基本操作を習得できるようにする

1. DaVinciバージョン別教材管理を追加する
2. 利用者向け「学習」画面を追加する
3. 教材進捗と職員承認を追加する
4. 操作別の短い練習課題を追加する
5. 基礎修了後に統合練習へ進む導線を追加する

### Phase 3: 生成処理を共通化する

1. `poc/scene/*`と`scripts/video/*`で共通の編集指示型を使用する
2. 字幕・テロップ・安全領域・BGM仕様を共通モジュールにする
3. 手順書、画面表示、CSV/Markdownを同じデータから生成する
4. 古い生成済み案件を再生成または移行できるようにする

## 8. 公開前整合性チェック

職員が課題を公開する前に、次を自動確認する。

- すべての指示行に、存在する音声・映像素材が指定されている
- 指示書の字幕スタイルと完成見本の字幕スタイルが同じである
- 図解の重要領域が字幕安全領域と重なっていない
- 強調テロップの文字とスタイルが指定されている
- 動きが必要なシーンに動画素材または編集可能パーツがある
- 見本と素材でBGMファイルが一致している
- 利用者向け指示に小数秒の絶対時刻が含まれていない
- `gapAfterFrames`が0以上の整数である
- 出力仕様が全画面で一致している
- 操作説明教材の対象DaVinciバージョンが表示されている

重大な不一致は公開エラーにし、職員画面で修正箇所を日本語で表示する。

## 9. 完了条件

次の条件をすべて満たしたら、今回の改善を完了とする。

1. 新規利用者がアプリ内で基礎学習の順番を確認できる
2. 職員がDaVinciの対象バージョンと教材を登録・更新できる
3. 利用者が教材動画と代替テキスト手順を閲覧できる
4. 教材の完了状況を利用者と職員の双方が確認できる
5. 利用者向け編集指示に開始・終了の小数秒が表示されない
6. 間が必要な箇所だけ整数フレームで表示される
7. 字幕指示と完成見本が同じスタイルになる
8. 図解が字幕安全領域と重ならない
9. 強調テロップの仕様が具体的に表示される
10. 見本で動くシーンには、対応する動く素材が支給される
11. 支給素材だけで指示された完成形を作れる
12. 矛盾した案件は公開前検査で止まる
13. 提出後に、利用者が現在の状態と次の行動を確認できる
14. AI採点が失敗しても職員レビュー一覧に提出物が表示される
15. 既存のふりがな、読み上げ、ステップ表示、再提出機能が維持される
16. lint、型チェック、関連テスト、production buildが成功する

## 10. Astra 6へ渡す実装プロンプト（方向性確定後に使用）

このプロンプトは、依頼者との打ち合わせで開発範囲と方向性が決まった後に使用する。未決定事項は、会議結果に合わせて書き換えてからAstra 6へ渡す。

```text
あなたは、このリポジトリの実装を担当するシニアエンジニアです。

この修正内容は、開発者が依頼したものではなく、依頼者から開発者へ共有されたものです。会議で合意済みの範囲だけを実装対象とし、未決定の教材内容、完成デザイン、担当範囲を独自に確定しないでください。

対象:

最初に必ず次を行ってください。

4. Next.js関連コードを変更する前に、AGENTS.mdの指示に従って、このリポジトリに入っているNext.js 16.2.10の該当ドキュメントをnode_modules/next/dist/docs/から確認する。
5. 現在のデータフローを、scene生成、素材生成、案件登録、利用者画面、提出、職員レビューに分けて確認する。

目的:
現在は案件と素材を渡せても、利用者がDaVinci Resolveの基本操作を習得する導線がなく、さらに指示書、支給素材、完成見本に不一致があります。利用者が基本操作を学び、支給素材と分かりやすい指示だけで動画を編集し、提出後の流れまで理解できる状態にしてください。

最優先で解決する問題:
- 24fps案件なのに、利用者向け指示が0.1秒単位の絶対開始・終了時刻になっている。
- 字幕の色分け指示と完成見本の表示方法が一致していない。
- 「図解を画面いっぱいに置く」と字幕安全領域が矛盾している。
- 強調テロップのフォント、サイズ、色、位置が明記されていない。
- BGMの指示と見本の音量基準が統一されていない。
- 完成見本では図解が動くが、利用者には全表示後の静止画1枚しか支給されない。
- 提出後の状態と次の行動が利用者に分かりにくい。
- AI採点に失敗すると、提出済みでも職員レビュー用feedbackが作られない可能性がある。
- DaVinciの対象バージョンに合った基礎教材と進捗管理がない。

実装方針:
1. 利用者向け編集指示と内部レンダリングタイムラインを分離する。
2. 利用者向け指示は、順番、シーン、セクション、映像タイプ、話者、セリフ、音声ファイル、映像素材、必要な間、補足を基本項目にする。
3. 利用者向け指示から絶対開始秒・終了秒を外す。
4. 間が必要な箇所だけgapAfterFramesとして0以上の整数で指定する。
5. 内部タイミングはstartFrame/endFrameで保持し、24fpsのフレーム境界に合わせる。
6. 字幕、強調テロップ、図解安全領域、BGMのスタイルを共通データとして定義し、完成見本と指示書を同じデータから生成する。
7. 見本で動きが必要なシーンは、初期実装ではアニメーション済みMP4/WebMを素材ZIPへ含める。静止画しか支給しない場合、そのシーンの見本も静止画で再現できる演出にする。
8. 課題公開前に、見本、指示、支給素材の整合性検査を行う。重大な不一致があれば公開させない。
9. 提出時は、AI採点の成否に関係なく職員確認用レコードを必ず作る。AI結果は同じレコードへ後から追記するか、明確に関連づける。
10. 利用者画面に提出状況タイムラインを表示し、「現在の状態」「現在の担当」「利用者が次にすること」「最終更新日時」を示す。
11. DaVinciバージョン別の教材管理、利用者の学習画面、教材進捗、職員確認を追加する。
12. 教材動画が用意されていない場合でも作業できるよう、各教材に代替テキスト手順を持たせる。
13. 最新DaVinciバージョンをコードへ固定しない。職員が対象バージョン、教材URL、更新日を管理できるようにする。
14. 既存のふりがな、読み上げ、大きな文字、ステップ表示、休憩通知、提出・再提出を維持する。

推奨する進め方:
- Phase 1として、指示・素材・見本の不一致、公開前検査、提出レビュー停止問題、提出状況表示を実装する。
- Phase 2として、DaVinci基礎教材と進捗管理を実装する。
- Phase 3として、poc/scene/*とscripts/video/*の共通編集指示スキーマへの統合を進める。

実装上の注意:
- 既存マイグレーションは編集せず、新しい連番マイグレーションを追加する。
- SupabaseのRLSを必ず追加・確認する。利用者は自分の進捗だけを更新・閲覧でき、職員と管理者は教材と全利用者の進捗を管理できるようにする。
- task_materialsは案件単位の教材である。共通の基礎学習教材は、既存構造への無理な流用を避け、必要ならtutorial_modules/tutorial_progress等の専用テーブルを追加する。
- 新しい型はsrc/lib/types.tsとDB定義を一致させる。
- 生成済み案件を壊さない。新旧データを読み取れる移行期間を用意するか、再生成方法を明示する。
- 利用者画面の文言は専門用語を減らし、短い文で次の行動が分かるようにする。
- 変更範囲を広げる前に既存の二重実装を確認し、どの生成経路が本番で使われているかを根拠付きで判断する。

必要なテスト:
- 利用者向け指示に小数秒の開始・終了が出ない。
- gapAfterFramesが整数でない場合は検証エラーになる。
- 動く見本に静止画しかない案件は公開前検査で失敗する。
- 字幕・強調テロップの共通スタイルが見本と指示書へ同じ内容で反映される。
- AI採点が失敗しても職員レビュー待ちに提出が表示される。
- 利用者は他人の教材進捗を閲覧・更新できない。
- 職員は教材を作成、公開、更新できる。
- 提出状態ごとに正しい「次にすること」が表示される。

作業の完了報告には次を含めてください。
- 何を変更したか
- なぜその設計にしたか
- 追加したマイグレーション
- 変更した利用者フローと職員フロー
- 実行したテストと結果
- 残っている教材制作作業。特にDaVinci操作説明動画そのものは、対象バージョンを確認して人が制作・登録する必要があること
- 既知の制限と安全な移行方法

まずリポジトリを調査し、実装計画を短く提示した後、そのままPhase 1の実装、検証まで進めてください。質問がなくても安全に判断できる範囲は自律的に進めてください。外部教材のURLやDaVinciの対象バージョンが未確定の場合は、値を捏造せず、職員が後から登録できる仕組みと未設定表示を実装してください。
```
