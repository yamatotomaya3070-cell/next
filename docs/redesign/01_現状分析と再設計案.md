# 01. 現状分析と再設計案

> 「つなぐワークス」動画制作システムを、「高品質な初心者向け金融解説YouTube動画を制作できること」というゴールから逆算して評価する。コード・DB・AIプロンプト・レンダリング・UI・仕様書の全レイヤーを実ファイルで精読した事実に基づく。**実装は未変更。**

## 最重要の発見

このシステムは現状、**「完成YouTube動画を作る」ためには設計されていない**。

- レンダラ（`render.ts:5`）には「AIは使わない」と明記され、ffmpegによる**静止画の機械合成**のみを行う。
- 練習素材系（practice）は**テロップ・図解をあえて焼き込まない** — それを付ける作業こそが就労者の訓練だから。
- つまり本システムの現在の目的は「編集訓練用の素材と課題を作ること」であり、ゴール（図解40–50%・数字アニメ・テンポ編集を備えた完成動画）とは**別の製品**を指している。

両立させるには、AIの役割を「発話台本の生成」から「**シーン単位の映像設計図の生成**」へ引き上げるのが再設計の核になる。

## 1. 現状アプリ概要

アプリ名は **「つなぐワークス（動画編集ワークサポート）」**（`login/page.tsx:42`）。Next.js 16 + Supabase。ロールは `trainee / staff / admin` の3種（`lib/types.ts:6`）。

実態は **「AIが動画編集の練習課題・受注案件を生成 → 職員が承認・配布 → 就労者が外部の編集ソフトで作業 → 成果物をアップロード → AIが採点下書き → 職員が承認」** という、eラーニング兼・受注制作の業務システム。ブラウザ内に動画エディタは無く（意図的にスコープ外／`docs/00003:69`）、編集はファイル受け渡し方式。

設計は3世代が地層のように積み重なっている：

- **第1世代（MVP）**：練習課題の生成→承認→配布→提出→AI採点（migration 00001/00002）
- **第2世代**：AIによる素材動画の自動生成（台本→TTS→ffmpeg合成→正解データ）とテンプレート化、機械検品（00004/00006/00007/00008）
- **第3世代（最新）**：スタイルガイド固定＋キャラ立ち絵の資産化＋練習素材ジョブ＋実写Bロール＋参考動画の取り込み・理解（00012–00016）

AI依存箇所はすべて `GEMINI_API_KEY` の有無で Gemini ↔ mock を自動切替し、失敗時も mock にフォールバックする。**キー未設定でも全機能がモックで動く**のが設計の核（`ai/index.ts:23`）。

## 2. 現状の動画制作フロー

動画生成には**目的の異なる2系統**が独立して存在する。

### 系統① practice（練習素材生成）— 現行の主眼

```
スタイルガイド → テーマ入力 → 台本生成(発話segment) → 立ち絵資産
  → TTS＋ffmpeg → clip_NNN.mp4(背景+立ち絵+音声) → ZIP配布 → 就労者が編集
```

各 clip は「背景静止画＋立ち絵1体＋音声」だけ。テロップ・図解・話者名・BGMすべて無し（`practice-render.ts:6`）。`must` 優先クリップを `concat -c copy` で無加工連結して完成見本 `sample.mp4` を作る（`practice-render.ts:128`）。

### 系統② video_jobs（テンプレ動画生成）— 先行実装

```
テンプレ選択 → 台本生成(シーン配列) → TTS → 字幕生成 → ffmpeg合成 → 完成見本+素材 → tasks登録 → 就労者が編集
```

②が焼き込むのは「静止背景（or Pexels実写ループ）＋静止立ち絵の表示ON/OFF（喋らない側は減光）＋静止テキストカード＋話者色分けASS字幕＋薄いBGM」まで。**ズーム・パン・トランジション・エフェクト・図解アニメは皆無**。

職員導線はほぼ全工程が画面化済み（スタイルガイド確定→AI生成→承認・公開→配布→レビュー→本番移行判定）。

## 4. 問題点（動画品質を下げている原因・優先順）

1. **【根因】シーンに「映像設計」データが存在しない** — 台本は発話の羅列で `visual_type / image_prompt / camera_motion / infographic / transition / se` が無い。全品質問題の上流。
2. **図解・数字アニメの生成能力が皆無** — 金融解説の核（40–50%）を作る手段がゼロ。最大のギャップ。
3. **シーン粒度が「発話1つ＝1シーン」で映像単位でない** — 3–10秒ごとに視覚変化する担保がない。
4. **Image-to-Video 完全欠如・カメラワーク指定なし**。
5. **テンポ編集不可**（`concat -c copy` の等速無加工）。
6. 図解要否をAIが判断しない／キャラは静止PNG4表情の切替のみ／SE皆無・BGM全体固定。
7. 品質管理・金融正確性の器がない（内容ベース検品・出典管理が未実装）。

## 5. 理想フロー（完全ハイブリッド）

```
テーマ → PROJECT(企画) → SCRIPT(7段構成) → SCENE分解(全項目)
  → CHARACTER参照(マスター固定) → アセット生成(画像/i2v/TTS/図解データ)
  → シーン単位割当(難易度別) → 就労者が編集 → 職員が品質管理 → 完成
```

**戦略＝完全ハイブリッド**：AIは精密なシーン設計図＋見本品質の完成見本＋素材を作る。安く決定論的なもの（立ち絵・ナレ・背景・テロップ下書き・数値データ・簡単な図解）は自動生成し、AIが見本品質まで完成見本をレンダリング。本番品質の仕上げは就労者が設計図＋完成見本に沿って制作。

**AI完成見本の二重の役割**：①就労者に「目指すべき完成形」を示す ②AIレビュー／機械検品に「提出物を照合する正解」を与える。完全自動レンダリング（戦略A）は巨大かつ就労者の作業＝事業価値を奪うため非採用。

## 7. 改修優先順位

- **P0（成立に不可欠）**：SCENEデータモデル＋AIシーン生成（responseSchema）／7段SCRIPT＋PROJECT層／CHARACTER_MASTER昇格／図解・数字アニメの最小実装／シーン単位タスク分解。
- **P1**：image/i2vプロンプトのシーン紐付け＋i2v配線／テロップ・BGM・SE・transitionの構造化／visual_type自動選択／金融出典管理。
- **P2**：テンポ編集／口パク・簡易モーション／内容ベース検品／難易度別カリキュラム。
- **P3**：完全自動レンダリング（部分適用）／実案件RAG本格化／テナントRLS。

## 8. データ構造改善案

**PROJECT / SCRIPT / SCENE / ASSET / TASK / CHARACTER** の6層に整理。既存を昇格できるものが多い。

- **CHARACTER_MASTER**（既存を昇格）：`style_guides.characters[]` を独立参照キーに。seedと立ち絵資産の一貫性は既存の強み。
- **PROJECT**（新設）：theme / target_audience / purpose / duration / title_candidates / thumbnail_concept / after_state。
- **SCRIPT**（拡張）：発話に `section`（hook/problem/basics/example/dialogue/caution/summary/cta）を付与。
- **SCENE**（新設・最重要）：scene_id / start/end/duration / section / narration / dialogue / visual_type / visual_description / image_prompt / image_to_video_prompt / camera_motion / character / character_expression / infographic / on_screen_text / subtitle / bgm / se / transition / editing_instruction / required_asset / quality_check。
- **ASSET**（拡張）：character_assets を維持しつつ、シーン紐付けアセットを scene_id + kind + storage_path + status で管理。
- **TASK**（拡張）：SCENE_TASK（scene_id × 作業種別 × 難易度 × 担当者 × ステータス）を新設。

> ※ 最新のSCENE schemaは 04 を正とする（音声を `audio[]` 配列化し、不要フィールドを統合・削除した版）。

## 9. UI改善案

- **職員**：プロジェクト＝1動画のシーンボード／シーン単位の承認・修正依頼／AI生成内容のレビュー（設計図・図解データ・i2vプロンプト）／視覚バリエーション比率の品質ダッシュボード。
- **就労者**：シーン単位「今日やること」カード（使用素材／ナレーション／やること／見本／チェック／完了。JSONは見せない）／既存の StepViewer・セルフチェック・提出をシーン粒度に適用／難易度別（LEVEL1–5）の作業出し分け。

改修の本質は新機能より、**作業単位を「案件」から「シーン」へ落とすこと**と**シーン設計図をUIに露出すること**。既存コンポーネントの多くが再利用できる。

## 10. 仕様書変更案

| 対象 | 現在の思想 | あるべき仕様への変更 | 理由 |
|------|-----------|--------------------|------|
| レンダリング（`render.ts:5`/docs00007） | AIは描画に使わず静止合成 | AIがシーン設計図を生成、図解・数字アニメ・i2vを段階導入 | 静的合成ではYouTube品質に構造的に到達不能 |
| 台本スキーマ（docs00007） | 発話segment | SCENEスキーマ（映像20項目）へ拡張・responseSchema厳格化 | 映像設計情報が欠落し台本止まり |

| 品質パイプライン（docs00011） | Loop A(生成)/Loop B(検品) | 間に「映像設計層」を第3の軸として追加 | 何を映すかの設計が不在 |
