# 開発者向け 動画編集システム改善の方向性打ち合わせ

実施日: 2026-09-11  
参加時の立場: 修正内容を受領した開発者  
目的: 受領した指摘をそのまま実装確定事項とはせず、依頼者と改善方針、範囲、優先順位、必要素材を確認する。

## 1. この打ち合わせに対する正しい認識

開発者である自分が修正依頼書を作成して提出したわけではない。

今回の流れは次のとおりである。

1. 廣田さんが実際にDaVinci Resolveで動画を編集した
2. 操作説明、指示書、支給素材、完成見本、提出後の流れに問題が見つかった
3. その確認内容を依頼者側が文章にまとめた
4. 開発者である自分が、その文章を修正内容として受領した
5. 今日の打ち合わせで、指摘を踏まえてどの方向へ改善するかを依頼者と相談する
6. 打ち合わせ後に、開発者が仕様、作業範囲、実装順、見積もりを整理する

今日の目的は、開発者側の改善案を承認してもらうことではない。受領した内容について認識を合わせ、依頼者が求める完成状態を明確にすることである。

## 2. 開発者として最初に伝える内容

> お送りいただいた修正内容を確認し、現在のシステム実装とも照合しました。秒数指定、字幕、図解サイズ、強調テロップ、BGM、動く見本と静止画素材、提出後の流れについては、実装上も確認できる点があります。ただし、すべてがシステム改修だけで解決する内容ではなく、教材の更新、完成デザインの決定、支給素材の作り方、運用方法も関係しています。本日は、利用者が最終的にどこまで編集できる状態を目指すのかを確認し、そのうえでシステム対応、教材対応、運用対応に分けて進め方を整理したいです。

## 3. 開発者が確認できた事実

### システム上で確認できたこと

- 動画仕様は24fpsになっている
- 利用者向けタイミング表は0.1秒単位の絶対開始・終了時刻を出している
- 指示書には、字幕本文を話者ごとの色に変えるように読める記載がある
- 見本側は、話者名と左帯を話者色にし、字幕本文は共通色にしている
- 「図解を画面いっぱいに置く」という文言が自動生成される
- 強調テロップの具体的なフォント、サイズ、色、位置が利用者向けに十分示されない
- BGMは「−20dBくらい」という文言が固定されている
- 見本は時間に合わせて数字、グラフ、項目などを動かしている
- 支給図解は、動きが完了した状態の静止画1枚として出力される
- 提出後はレビュー待ちになる仕組みがある
- AI採点に失敗しても提出は成立するが、職員レビューに必要なデータが作られない可能性がある
- DaVinci Resolveの基本操作を順番に学ぶ専用コースは現在ない

### システムだけでは決められないこと

- 現場で使用するDaVinci Resolveの対象バージョン
- 操作説明動画を誰が制作・更新するか
- 字幕の正しい完成デザイン
- 図解をどの大きさ・位置に置くか
- 強調テロップの正しいデザイン
- BGMの正しい音量感
- 利用者にアニメーション制作まで求めるか
- 完成見本を利用者へ見せるか
- 提出後に誰がいつまでに確認するか

これらは依頼者との打ち合わせで決める必要がある。

## 4. 修正内容の分類

| 分類 | 内容 | 主な担当 |
|---|---|---|
| システム改修 | 指示書形式、学習画面、進捗、素材生成、公開前検査、提出状況、レビュー処理 | 開発者 |
| 教材制作 | 現在のDaVinci画面に合う操作説明動画、画像付き手順 | 依頼者側で内容決定。制作担当は会議で確認 |
| デザイン決定 | 字幕、強調テロップ、図解位置、BGM基準 | 依頼者側で正しい完成形を決定 |
| 素材方針 | 動く素材を支給するか、利用者が作るか | 依頼者と開発者で実現方法を相談 |
| 運用決定 | 教材更新、提出確認、修正、完了の担当と期限 | 依頼者側を中心に決定 |
| 実務検証 | 新しい指示書と支給素材だけで編集できるか | 廣田さん等の動画編集経験者 |

## 5. 今日の打ち合わせで依頼者へ確認すること

### 最終目標

1. 利用者に最初に身につけてもらう編集作業はどこまでか。
2. 「素材を順番に並べ、字幕、BGM、間を調整して書き出す」ことを最初の到達点としてよいか。
3. 数字、グラフ、人物などのアニメーション制作も初期段階から必要か。
4. 最終的には一般の動画編集案件を一人で行えるところまで目指すのか、決められた工程を担当できればよいのか。

### 操作説明教材

5. 現場で使うDaVinci Resolveのバージョンは何か。
6. 操作説明動画は依頼者側から支給されるのか、開発側で収録まで担当するのか。
7. DaVinciのバージョン更新後、誰が教材の内容を確認するのか。
8. 動画だけでなく、画面画像付きの手順も必要か。

### 編集指示

9. 秒数指定を原則やめ、素材名、セリフ、順番を中心にする方針でよいか。
10. 間を指定するときだけ「12フレーム空ける」などと記載する形でよいか。
11. 字幕本文を話者色にするのか、見本どおり話者名・帯だけを色分けするのか。
12. 図解は字幕と重ならない安全領域へ配置する方針でよいか。
13. 強調テロップのフォント、サイズ、色、位置は何を正とするか。
14. BGMは「−20dB」を正とするのか、見本の聴感を正とするのか。

### 見本と支給素材

15. 完成見本を利用者へ提出前から見せるか。
16. 見せない場合、素材と指示書だけで完成形を判断できる状態にすることでよいか。
17. 見本で動いている図解は、アニメーション済み動画として支給してよいか。
18. 利用者自身に動きを作らせる場合、それを学ぶ教材と具体的な編集指示も作るのか。

### 提出後

19. 提出後、誰が最初に確認するか。
20. 利用者へ何日程度で結果を返すか。
21. 「AI確認中」「職員確認待ち」「修正してください」「完了」の表示でよいか。
22. AI確認に失敗した場合も、職員へ必ず回す運用でよいか。

## 6. 開発者から提示する方向性案

以下は確定仕様ではなく、依頼者と相談するための案である。

### 推奨する学習順

1. DaVinci Resolveの基本操作を短い教材で確認する
2. 素材の読み込み、音声配置、字幕、BGM、書き出しを個別に練習する
3. 30〜60秒の短い統合練習を行う
4. 問題なく完成できた後に、現在のような長い動画案件へ進む
5. アニメーション制作は、基本編集ができるようになった後の別課題にする

### 推奨する指示書

利用者向けには次を表示する。

- 順番
- シーン
- セクション
- 映像タイプ
- 話者
- セリフ
- 使用する音声ファイル
- 使用する画像・動画素材
- 必要な箇所だけ空けるフレーム数
- 字幕スタイル
- 強調テロップの具体的な仕様
- 補足

見本生成や自動検査で必要な細かい秒数は、利用者へ作業条件として見せず、システム内部で保持する。

### 推奨する素材

- 静止した図解はPNGで支給する
- 動きが完成条件に含まれる図解はMP4等の動画で支給する
- 利用者にアニメーションを作らせる課題では、分解済みパーツと具体的な設定値を支給する
- 見本にあるのに支給素材で作れない表現が残っている場合、課題を公開できないようにする

## 7. 開発者として用意しておくもの

- 受領した修正内容の原文
- 現在のタイミング表
- 現在の手順書・編集指示書
- 完成見本動画
- 利用者へ渡した支給素材ZIP
- 提出後のレビュー待ち画面
- 現在のシステムで確認できた事実の一覧
- 改善後の指示書サンプル
- システム対応、教材対応、運用対応の分類表

資料がすべて手元にない場合は、受領した文章と現在のコード確認結果をもとに方向性だけ決め、実物確認を宿題にする。

## 8. 会議中に避ける認識

- 受領した文章の全項目を、すでに確定した実装仕様として扱わない
- 操作説明動画の作り直しを、当然に開発者の担当だと決めない
- 字幕やBGM等の正しいデザインを開発者だけで決めない
- 利用者に求める編集技術の範囲を開発者側で勝手に広げない
- システム改修だけで利用者が編集可能になると断定しない
- 会議の場で工数や納期を即答せず、決定した仕様を確認してから整理する

## 9. 45分の進行例

| 時間 | 内容 | 開発者の役割 |
|---|---|---|
| 0〜5分 | 受領内容の認識確認 | 修正内容を受け取った立場であることを確認する |
| 5〜15分 | 各指摘の事実確認 | コード上で確認できた点と、確認できない点を分けて説明する |
| 15〜25分 | 目標確認 | 利用者に求める最終到達点を質問する |
| 25〜35分 | 改善方向の相談 | 学習、指示書、素材、提出フローの案を提示する |
| 35〜42分 | 担当と優先順位 | システム、教材、デザイン、運用の担当を確認する |
| 42〜45分 | 次の作業確認 | 開発者が仕様案を作るために必要な回答と素材を確認する |

## 10. 会議後に開発者が行うこと

1. 決定事項と未決定事項を分けて議事録にする
2. システム改修、教材制作、運用変更へ分類する
3. システム改修を優先度別に分ける
4. 影響する画面、DB、生成処理を確定する
5. 実装工数と順序を整理する
6. Astra 6へ渡す実装プロンプトへ会議の決定事項を反映する
7. 30〜60秒の試験課題で検証してから長い課題へ反映する

## 12. 会議後の依頼者への返答例
