# 開発者向け 対応可否・完成条件・概算工数

作成日: 2026-09-11  
前提: 依頼者から受領した修正内容について、現在のコードを確認した時点での概算。正式見積もりは方向性打ち合わせ後に確定する。

## 1. 結論

受領した修正内容は、技術的には対応可能である。

ただし、次の3種類が含まれている。

1. 開発者だけで修正できるシステム上の問題
2. 依頼者が正しい完成形を決めた後に開発できる問題
3. 操作説明動画や教材素材など、コーディング以外の制作が必要な問題

特に工数が大きいのは、「見本動画では動いているが、支給素材は静止画」という問題である。動く素材を自動生成して案件ごとに支給するところまで行う場合、指示文の修正だけではなく、素材生成、保存、ZIP同梱、画面表示、公開前検査まで変更する必要がある。

## 2. 各修正内容の対応可否

| 項目 | 対応可否 | 開発だけで完了するか | 対応内容 | 未決定事項 |
|---|---|---|---|---|
| DaVinci操作説明 | 対応可能 | 一部のみ | バージョン別の教材登録、表示、進捗管理を作る | 対象バージョン、動画内容、動画制作担当 |
| 秒数指定の廃止 | 対応可能 | はい | 利用者向け指示を順番中心に変更し、必要箇所だけフレーム指定にする | 何フレーム空けるかの基準 |
| 字幕の不一致 | 対応可能 | 決定後に可能 | 見本と指示書を共通スタイルから生成する | 本文色と話者色の正解デザイン |
| 図解サイズ | 対応可能 | 決定後に可能 | 字幕安全領域、Fit/Fill、背景処理を指定する | 正しい余白・位置・背景 |
| 強調テロップ | 対応可能 | 決定後に可能 | 文字、フォント、太さ、サイズ、色、位置を指示へ出す | 正しいデザイン値 |
| BGM | 対応可能 | 決定後に可能 | 見本と指示で同じ音源・基準を使う | −20dBか聴感か、測定基準を使うか |
| 動く見本と静止画素材 | 対応可能 | はい。ただし工数大 | 動きが必要なシーンにアニメーション済み動画を生成・支給する | 利用者に動きを作らせる範囲 |
| 提出後の流れ | 対応可能 | 一部のみ | 状況と次の行動を表示し、AI失敗時も職員レビューへ回す | 確認担当、返却期限、完了基準 |

## 3. 現状と改善後の違い

| 項目 | 現状 | 改善後 |
|---|---|---|
| 学習開始 | 案件を渡され、すぐ長い編集へ入る | 基本操作教材と短い練習を終えてから案件へ入る |
| DaVinciバージョン | 教材の対象バージョンを管理していない | 対象バージョン、更新日、教材URL、代替手順を管理する |
| 編集順 | 絶対開始・終了秒へ合わせる | 上から順に素材を配置する |
| 間の指定 | 0.1秒単位の絶対時間に含まれる | 必要な箇所だけ整数フレームで指定する |
| 内部時間 | 利用者向け指示と混在 | 見本生成・検品用として内部だけに保持する |
| 字幕 | 指示と見本の表現が異なる | 1つの字幕仕様を見本と指示書で共有する |
| 図解 | 「画面いっぱい」で字幕と重なる | 字幕安全領域内へ配置し、比率処理も指定する |
| 強調テロップ | 意味と表示仕様が曖昧 | 対象文字と具体的なデザインを表示する |
| BGM | −20dBという値と見本の聴感に差が出る | 同じ音源と共通基準で見本・指示・検品をそろえる |
| 動く図解 | 見本は動くが、素材は完成状態のPNG1枚 | 動くシーンにはアニメーション済み動画を支給する |
| 公開前確認 | 指示・素材・見本の矛盾を自動検査しない | 再現できない案件を公開前に止める |
| 提出後 | レビュー待ちだが、次の行動が分かりにくい | 現在の担当、状態、次の行動、更新日時を表示する |
| AI採点失敗 | 職員レビューへ出ない可能性がある | AIの成否に関係なく職員確認対象になる |

## 4. 完成の定義

「コードを変更した」だけでは完成としない。次の条件を満たして、利用者が実際に編集できた時点を完成とする。

### 4-1. システムの完成条件

- 職員が対象DaVinciバージョンと教材を登録できる
- 利用者が教材動画または画像付き手順を閲覧できる
- 利用者と職員が教材の完了状況を確認できる
- 利用者向け指示に小数秒の絶対開始・終了が表示されない
- 必要な間だけ「○フレーム」と表示される
- 字幕、図解、強調テロップ、BGMの指示が見本と一致する
- 見本で動くシーンには対応する動画素材が含まれる
- 支給素材ZIP内のファイル名と指示書のファイル名が一致する
- 支給されていない加工を利用者へ要求しない
- 矛盾した案件を公開前に検出できる
- 提出後の状態と次の行動が表示される
- AI採点が失敗しても職員が提出物を確認できる
- 既存のふりがな、読み上げ、ステップ表示、再提出が動く
- lint、型チェック、関連テスト、production buildが成功する

### 4-2. 実務上の完成条件

- 廣田さん等の経験者が、完成見本を見ずに、新しい指示書と支給素材だけで試験動画を完成できる
- 初学者が基本操作教材を見た後、支援員の常時操作代行なしで30〜60秒の試験動画を完成できる
- 初学者が素材を読み込み、順番に並べ、字幕、BGM、フレーム間隔、書き出し、提出まで行える
- 作業中に止まった箇所と質問内容を記録できる
- 提出後、利用者が待つのか、修正するのかを自分で判断できる
- 職員が提出物を確認し、修正または完了へ進められる

### 4-3. 試験課題の合格条件

最初は30〜60秒の動画で検証する。

- 音声2〜3個を指定順に配置できる
- 指定箇所に12フレームの間を入れられる
- 静止画1個を字幕安全領域内に配置できる
- アニメーション済み動画素材1個を配置できる
- 2話者分の字幕を指定スタイルで作れる
- 強調テロップ1個を指定どおり表示できる
- BGMを声の邪魔にならない音量にできる
- MP4/H.264、指定解像度、24fpsで書き出せる
- システムへ提出できる
- 職員が確認し、結果を返せる

経験者テストと初学者テストをそれぞれ1回以上行い、致命的な停止要因がなくなった時点で長い案件へ展開する。

## 5. 概算工数

1人の開発者がGPT-6 Astraを使用して実装する場合の目安。調査済みの現在コードを前提とする。1日を実働8時間としている。

### 5-1. 最小修正版

現在の7つの指摘と提出後の停止問題を直し、既存案件を編集可能に近づける範囲。新しい教材管理画面は含めず、教材動画は既存の仕組みへ手動登録する。

| 作業 | 工数目安 |
|---|---:|
| 仕様確定とサンプル設計 | 4〜8時間 |
| 利用者向け指示から絶対秒数を外す | 6〜10時間 |
| フレーム単位の間指定と内部時間の分離 | 8〜12時間 |
| 字幕・図解・強調テロップ・BGM仕様の統一 | 12〜20時間 |
| 動く図解を動画素材として支給 | 16〜28時間 |
| 公開前整合性チェック | 8〜14時間 |
| 提出状況表示とAI失敗時の職員レビュー | 8〜14時間 |
| 回帰テスト、ビルド、試験案件生成 | 8〜12時間 |
| 合計 | 70〜118時間 |

目安は約9〜15開発日である。

### 5-2. 推奨版

最小修正版に加えて、利用者が基本操作を学ぶための教材管理、進捗、学習画面、操作別練習まで実装する。

| 追加作業 | 工数目安 |
|---|---:|
| 教材・進捗のDBとRLS | 8〜14時間 |
| 職員向け教材管理画面 | 10〜18時間 |
| 利用者向け学習画面 | 12〜20時間 |
| 教材完了・職員確認・課題導線 | 8〜14時間 |
| 操作別の短い練習課題 | 12〜20時間 |
| アクセシビリティ・権限・結合テスト | 8〜14時間 |
| 追加合計 | 58〜100時間 |

最小修正版との合計は128〜218時間、約16〜28開発日が目安である。

### 5-3. コーディング以外の工数

次は開発工数に含めない。担当決定後に別途見積もる。

| 作業 | 目安 |
|---|---:|
| 対象DaVinciバージョンと完成デザインの決定 | 2〜4時間の打ち合わせ・確認 |
| 基本操作動画の台本・収録・編集 | 1本あたり2〜6時間 |
| 字幕、図解、強調テロップ、BGMの基準資料作成 | 4〜12時間 |
| 廣田さん等による経験者テスト | 2〜4時間 |
| 初学者による試験とヒアリング | 1人あたり2〜4時間 |
| テスト結果を受けた再調整 | 内容により1〜5開発日 |

## 6. 工数が変わる条件

### 工数が減る条件

- 字幕、強調テロップ、図解位置、BGMの正解デザインが会議で決まる
- 対象DaVinciバージョンが決まる
- 操作説明動画を依頼者側から支給してもらえる
- 動く図解はMP4を支給する方針で統一する
- 最初は1種類の動画テンプレートだけを対象にする
- 既存案件の自動移行を行わず、新規案件から新形式にする

### 工数が増える条件

- すべての既存動画テンプレートを同時に対応する
- 既存案件・既存ZIPも新形式へ自動移行する
- 利用者自身に複雑なアニメーションを作らせる
- DaVinciの複数バージョンへ同時対応する
- 教材動画の収録・編集まで開発者へ依頼する
- 自動採点で字幕デザインやアニメーションまで厳密に比較する
- 実際の利用者テストで大きな操作上の問題が見つかる

## 7. 現時点で推奨する契約・進め方

最初から推奨版全体を一括確定せず、次の単位で合意する。

### 第1段階: 仕様確定

- 依頼者が字幕、図解、強調テロップ、BGM、見本公開範囲を決める
- 開発者が変更対象と見積もりを確定する
- 30〜60秒の試験課題の完成形を決める

### 第2段階: 最小修正版

- 指示・素材・見本を統一する
- 提出後の停止問題を直す
- 試験課題を生成する

### 第3段階: 実務テスト

- 経験者が素材と指示書だけで作る
- 初学者が基本操作説明後に作る
- 問題点を記録する

### 第4段階: 学習機能

- テスト結果をもとに教材管理と学習画面を作る
- 長い案件へ展開する

## 8. 打ち合わせで伝える概算回答

> 現在いただいている内容は、技術的には対応可能です。ただし、操作説明動画や字幕・BGM等の正しい完成形は、システムだけでは決められないため、方向性の確認が必要です。既存の指示・素材・見本の不一致と提出フローを直す最小修正版は、現時点で約70〜118時間、9〜15開発日を見込んでいます。基本操作教材の管理、学習進捗、操作別練習まで含め、利用者が学習して編集できる仕組みにする推奨版は、合計約128〜218時間、16〜28開発日が目安です。教材動画の制作と利用者テストは別途必要です。まず30〜60秒の試験課題で成立を確認し、その後に長い案件へ展開する進め方が安全です。

## 9. 正式見積もりに必要な回答

- 開発者へ正式に依頼する範囲
- 対象とする動画テンプレート数
- 既存案件を移行するか、新規案件から対応するか
- 利用者へ完成見本を見せるか
- 利用者にアニメーション制作を求めるか
- 操作説明動画の制作担当
- 対応するDaVinciバージョン数
- 字幕、図解、強調テロップ、BGMの正解仕様
- 初回リリース希望日
- 経験者テストと初学者テストの担当者
